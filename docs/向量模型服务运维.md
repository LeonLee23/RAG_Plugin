# QZhou 向量模型：服务器/本机部署与 API 接入

本文面向新部署，使用仓库中的 [scripts/serve_embeddings.py](../scripts/serve_embeddings.py) 提供 HTTP API，不依赖特定云平台、个人路径、预装环境或演示密钥。模型部署在服务器与本机时使用同一脚本，区别在于安装环境和 RAG 后端访问它的地址。

RAG 后端的 `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、模型名及配置重载方法见 [使用说明书第 3.2 节](../使用说明书.md#32-常用配置项)。本文补充模型端如何启动、设置相同密钥，以及服务器与本机两种 API 接入方式。

所有命令中的 `<...>` 都要替换为自己的值；`embedding.example.com` 是示例域名。`127.0.0.1` 是通用回环地址，不是某台开发机的专属地址。除特别说明外，在下载或克隆后的**仓库根目录**执行命令，不要求固定盘符或目录。

## 1. 先确认部署条件

| 项目 | 要求与说明 |
| --- | --- |
| 模型 | `Kingsoft-LLM/QZhou-Embedding-Zh` 的完整 SentenceTransformer 模型，包含自定义代码、Tokenizer、池化和 `2_Dense` 投影等文件 |
| GPU | 当前脚本固定使用 `cuda`、`bfloat16` 和 SDPA，需要支持这些能力的 NVIDIA GPU；不是 CPU 或 macOS/MPS 启动方案 |
| 资源 | 8B 模型需要为权重、运行时及输入留出足够显存和内存；先用短文本探针验证，不能只按权重大小判断能否运行 |
| Python | 以下示例使用独立 Python 3.12 环境，与 RAG 项目的 `.venv` 分开 |
| 依赖 | 示例采用 PyTorch 2.9.0 / CUDA 12.8、Transformers 4.51.1、Sentence Transformers 3.4.1；驱动须兼容所选 PyTorch 构建 |
| 网络与磁盘 | 首次下载需能访问 Hugging Face，并为完整权重与缓存留足空间；权重保存到已被 Git 忽略的 `models/` |
| 服务协议 | `GET /health`，以及需要 Bearer 密钥的 `GET /v1/models`、`POST /v1/embeddings` |

先运行 `nvidia-smi` 确认驱动和可用显存。没有合适 GPU 的本机可运行 RAG 后端，并连接另一台服务器上的模型 API；本仓库没有提供 CPU 自动回退。

完整模型加载流程参考 [QZhou 官方模型说明](https://huggingface.co/Kingsoft-LLM/QZhou-Embedding-Zh#usage)。依赖基线沿用已有验证记录中的核心版本，但本文新增的从零安装流程仍需在目标机器验证，不代表所有硬件和系统均已实测。PyTorch wheel 的 CUDA 构建按驱动选择，安装选项见 [PyTorch 官方历史版本](https://pytorch.org/get-started/previous-versions/#v290)。

脚本通过 `trust_remote_code=True` 加载官方模型代码，只从可信模型仓库下载。需要固定复现版本时，可在下方 `snapshot_download` 中增加 `revision='<模型提交版本>'`；不要只下载基础模型权重或遗漏投影层。下载方式参考 [Hugging Face 完整仓库下载](https://huggingface.co/docs/huggingface_hub/guides/download#download-an-entire-repository)。

## 2. 方案一：在 Linux GPU 服务器部署

### 2.1 准备独立环境

通过自己的 SSH 地址登录服务器，下载或克隆本项目，并进入仓库根目录。以下命令在服务器的 Bash 中执行。需要预先具备 Python 3.12 及其 `venv` 支持；不要使用 RAG 后端的虚拟环境安装模型依赖。

```bash
nvidia-smi
QZHOU_ENV="$HOME/.venvs/qzhou-embedding"
python3.12 -m venv "$QZHOU_ENV"
source "$QZHOU_ENV/bin/activate"
python -m pip install --upgrade pip
python -m pip install torch==2.9.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install sentence-transformers==3.4.1 transformers==4.51.1 tokenizers==0.21.1 accelerate==1.3.0 fastapi==0.115.12 uvicorn==0.34.2 'numpy>=2,<3' 'huggingface-hub>=0.30,<1'
python -m pip check
python -c "import torch; assert torch.cuda.is_available(), 'CUDA unavailable'; assert torch.cuda.is_bf16_supported(), 'BF16 unavailable'; print(torch.__version__, torch.cuda.get_device_name(0))"
```

每条命令成功后再继续。若驱动不适配 CUDA 12.8，先从 PyTorch 官方安装说明选择匹配的构建，重新检查 GPU 能力。不要混用另一环境的 `.pth`、复制其库文件或修改全局 Python 来绕过依赖冲突。RAG 的 `uv sync --frozen` 不会安装模型服务的这些独立依赖。

### 2.2 下载完整模型

继续使用上面的模型环境，在仓库根目录执行：

```bash
python -c "from huggingface_hub import snapshot_download; snapshot_download(repo_id='Kingsoft-LLM/QZhou-Embedding-Zh', local_dir='models/qzhou-embedding-zh')"
python -c "from pathlib import Path; p=Path('models/qzhou-embedding-zh'); assert (p/'modules.json').is_file() and (p/'2_Dense').is_dir(), 'Incomplete model'; print('Model structure found')"
```

结构检查只验证关键目录存在，成功加载和真实编码才算部署通过。模型下载中断时可重新执行下载命令；不要把 `models/` 上传 GitHub。

### 2.3 设置密钥并启动

先自行生成并保存一段足够随机的密钥，在下面的提示中输入。同一个值稍后填入 RAG 的 `.env`；不要使用文档占位符作为密钥。

```bash
export CUDA_VISIBLE_DEVICES=0
export OMP_NUM_THREADS=4
export MKL_NUM_THREADS=4
read -rsp 'Embedding API key: ' EMBEDDING_API_KEY
printf '\n'
export EMBEDDING_API_KEY
mkdir -p data
python -u scripts/serve_embeddings.py --model-dir models/qzhou-embedding-zh --port 6006 2>&1 | tee -a data/qzhou-embedding.log
```

这条命令在前台运行，模型加载完成后才监听端口。服务器上的模型脚本只读取进程环境变量，不会自动读取 RAG 的 `.env`。关闭终端后重新运行，需要重新设置密钥并激活模型环境。

需要断开 SSH 后继续运行时，可先安装并使用 `screen`：在仓库根目录运行 `screen -S qzhou-embedding`，在新会话中执行 `source "$HOME/.venvs/qzhou-embedding/bin/activate"`，再执行本节启动命令；按 `Ctrl+A`、再按 `D` 离开会话。不要在旧服务运行时重复启动。

当前脚本监听 `0.0.0.0:6006`，但它没有自动配置防火墙、云安全组、HTTPS 或域名。只向需要访问的客户端开放端口；跨公网传递密钥和文档时，应使用 HTTPS 网关或受保护的网络。网关必须保留 `/v1` 路径与 `Authorization` 请求头。

### 2.4 RAG 接入服务器 API

在**运行 RAG 后端的机器**配置 `.env`。使用已配置的 HTTPS 网关时：

```dotenv
EMBEDDING_BASE_URL=https://embedding.example.com/v1
EMBEDDING_MODEL=Kingsoft-LLM/QZhou-Embedding-Zh
EMBEDDING_API_KEY=<第2.3节设置的实际密钥>
EMBEDDING_TIMEOUT_SECONDS=120
```

`https://embedding.example.com/v1` 需要替换为自己实际可用的网关地址；脚本自身只提供 HTTP。若通过可信内网直连，Base URL 使用 `http://<模型服务器内网地址>:6006/v1`。公网端口映射或网关使用其他端口时，填写对客户端公开的实际端口，不照抄 6006。

随后按使用说明书重建后端容器或重启主机后端，并执行第 4 节检查。RAG 后端可以在主机或容器里，但必须从它实际运行的网络环境验证该地址；浏览器能打开服务器并不能证明容器也能连接。

## 3. 方案二：在本机部署

本机运行模型仍是一个独立 HTTP 服务；RAG 只调用它的 API。Linux 本机直接执行第 2.1～2.3 节即可，省去 SSH。下面提供 Windows PowerShell 的完整安装与启动方法。

### 3.1 Windows 安装与模型下载

需要支持 CUDA/BF16 的 NVIDIA GPU、可用驱动和 Python 3.12。进入仓库根目录执行。模型环境放在用户目录下、仓库之外，使用解释器完整路径，无需修改 PowerShell 全局执行策略。

```powershell
nvidia-smi
$QzhouEnv=Join-Path $env:USERPROFILE '.venvs/qzhou-embedding'
py -3.12 -m venv $QzhouEnv
$QzhouPython=Join-Path $QzhouEnv 'Scripts/python.exe'
& $QzhouPython -m pip install --upgrade pip
& $QzhouPython -m pip install torch==2.9.0 --index-url https://download.pytorch.org/whl/cu128
& $QzhouPython -m pip install sentence-transformers==3.4.1 transformers==4.51.1 tokenizers==0.21.1 accelerate==1.3.0 fastapi==0.115.12 uvicorn==0.34.2 'numpy>=2,<3' 'huggingface-hub>=0.30,<1'
& $QzhouPython -m pip check
& $QzhouPython -c "import torch; assert torch.cuda.is_available(), 'CUDA unavailable'; assert torch.cuda.is_bf16_supported(), 'BF16 unavailable'; print(torch.__version__, torch.cuda.get_device_name(0))"
& $QzhouPython -c "from huggingface_hub import snapshot_download; snapshot_download(repo_id='Kingsoft-LLM/QZhou-Embedding-Zh', local_dir='models/qzhou-embedding-zh')"
& $QzhouPython -c "from pathlib import Path; p=Path('models/qzhou-embedding-zh'); assert (p/'modules.json').is_file() and (p/'2_Dense').is_dir(), 'Incomplete model'; print('Model structure found')"
```

如果没有 `py` 启动器，可将 `py -3.12` 替换为本机 Python 3.12 的实际命令；其余步骤仍使用 `$QzhouPython`。每条命令成功后再继续，不要在下载或依赖安装失败后直接启动。

### 3.2 Windows 设置密钥并启动

在同一 PowerShell 终端执行：

```powershell
$env:CUDA_VISIBLE_DEVICES='0'
$env:OMP_NUM_THREADS='4'
$env:MKL_NUM_THREADS='4'
$QzhouSecret=Read-Host '输入自定义的 Embedding API Key' -AsSecureString
$env:EMBEDDING_API_KEY=[System.Net.NetworkCredential]::new('', $QzhouSecret).Password
New-Item -ItemType Directory -Force -Path 'data' | Out-Null
& $QzhouPython -u scripts/serve_embeddings.py --model-dir models/qzhou-embedding-zh --port 6006 2>&1 | Tee-Object -FilePath 'data/qzhou-embedding.log' -Append
```

保持终端运行，并把相同密钥填入 RAG `.env`。新开终端时需要重新定义 `$QzhouEnv`、`$QzhouPython` 和环境变量。当前脚本也会监听本机所有网卡；仅本机使用时，不向外部网络开放此端口。

### 3.3 RAG 接入本机 API

按照 **RAG 后端运行在哪里** 选择 `.env` 中的地址：

| 模型位置 | RAG 后端位置 | `EMBEDDING_BASE_URL` |
| --- | --- | --- |
| 本机主机进程 | 同一主机进程 | `http://127.0.0.1:6006/v1` |
| 本机宿主机进程 | Docker Desktop 容器 | `http://host.docker.internal:6006/v1` |
| Linux 宿主机进程 | Linux Docker Engine 容器 | 配置下方主机映射后使用 `http://host.docker.internal:6006/v1` |
| 另一台机器 | 主机或容器 | 第 2.4 节的实际服务器 API 地址 |

其他字段不变：`EMBEDDING_MODEL=Kingsoft-LLM/QZhou-Embedding-Zh`，`EMBEDDING_API_KEY` 等于启动模型时输入的密钥，超时按需要设置。容器内的 `127.0.0.1` 指容器自身，不能用它访问宿主机模型。Docker Desktop 的主机访问方法见 [Docker 官方说明](https://docs.docker.com/desktop/features/networking/networking-how-tos/#connect-a-container-to-a-service-on-the-host)。

Linux Docker Engine 如未解析 `host.docker.internal`，在仓库根目录新建 `compose.host.yaml`：

```yaml
services:
  backend:
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

用该附加配置启动或重建后端：

```bash
docker compose -f compose.yaml -f compose.host.yaml config --quiet
docker compose -f compose.yaml -f compose.host.yaml up -d --force-recreate backend
```

后续管理这套部署时保持相同的 `-f` 组合，避免重建时丢失映射。模型服务需允许来自 Docker 网桥的连接，防火墙也需允许相应来源。映射机制见 [Docker host-gateway 说明](https://docs.docker.com/reference/cli/docker/container/run/#add-host)。若模型运行在 WSL 等独立网络环境中，先确认后端到该环境的实际路由，不假设 Windows、WSL 与容器共享同一回环地址。

## 4. 验证两种部署的 API

### 4.1 先检查 HTTP 与鉴权

模型机器上用浏览器或 HTTP 客户端访问 `http://127.0.0.1:6006/health`，应得到 `{"status":"ok"}`。Linux 可以运行 `curl -fsS http://127.0.0.1:6006/health`；Windows 可以运行 `Invoke-RestMethod 'http://127.0.0.1:6006/health'`。

健康接口不要求密钥，也不执行编码。`GET <Base URL>/models` 与 `POST <Base URL>/embeddings` 必须带 `Authorization: Bearer <实际密钥>`；缺少密钥或密钥错误返回 401。模型列表接受全名 `Kingsoft-LLM/QZhou-Embedding-Zh` 与别名 `qzhou-embedding-zh`。

### 4.2 直接调用 API：共用 Python 探针

服务器与本机使用同一请求格式。以下代码只依赖 Python 标准库，保存为 `data/check_embedding_api.py`（先创建 `data` 目录）。它从运行探针的终端读取 Base URL，交互输入密钥，不把密钥写入文件或打印向量；只发送自建样例，必须显式传 `--live-model` 才执行。

```python
import argparse
import getpass
import json
import math
import os
import urllib.request

parser = argparse.ArgumentParser()
parser.add_argument('--live-model', action='store_true', required=True)
parser.parse_args()
base_url = os.environ['EMBEDDING_BASE_URL'].rstrip('/')
api_key = getpass.getpass('Embedding API key: ')
headers = {'Authorization': f'Bearer {api_key}'}
request = urllib.request.Request(base_url + '/models', headers=headers)
with urllib.request.urlopen(request, timeout=30) as response:
    names = [item['id'] for item in json.load(response)['data']]
assert 'Kingsoft-LLM/QZhou-Embedding-Zh' in names, names

body = {
    'model': 'Kingsoft-LLM/QZhou-Embedding-Zh',
    'input': ['This sentence: <|im_start|>“凤凰项目使用星河数据库。” means in one word: “'],
}
request = urllib.request.Request(
    base_url + '/embeddings',
    data=json.dumps(body).encode('utf-8'),
    headers={**headers, 'Content-Type': 'application/json'},
    method='POST',
)
with urllib.request.urlopen(request, timeout=120) as response:
    item = json.load(response)['data'][0]
assert item['index'] == 0
vector = item['embedding']
assert len(vector) == 1792 and all(math.isfinite(x) for x in vector)
norm = math.sqrt(sum(x * x for x in vector))
assert abs(norm - 1) < 0.01, norm
print({'dimension': len(vector), 'norm': norm, 'ok': True})
```

在能访问模型的 Linux 终端执行（示例验证模型本机地址；跨机器时替换为第 2.4 节实际地址）：

```bash
export EMBEDDING_BASE_URL='http://127.0.0.1:6006/v1'
python data/check_embedding_api.py --live-model
```

Windows PowerShell 的等价命令：

```powershell
$env:EMBEDDING_BASE_URL='http://127.0.0.1:6006/v1'
py -3.12 data/check_embedding_api.py --live-model
```

这两个命令从主机发起请求；若检查 Docker 后端，仍要执行下一节的容器探针。独立探针不会读取 `.env`，因此需显式设置当前终端的地址。

服务返回完整的 1792 维归一化向量；RAG 的 `app/embeddings.py` 取前 512 维后再次归一化并存储。直接调用者须像示例一样添加 PromptEOL 模板；RAG 后端已经添加，不要在服务端重复包装。查询输入还需添加检索指令，具体拼装以 [app/embeddings.py](../app/embeddings.py) 为准。

当前脚本每次接收 1～32 段非空文本，每段最多 4096 tokens；超限返回 422，不静默截断。GPU 推理串行执行，内部 batch_size 为 2。不要用未经过完整投影的基础模型输出替代此 API。

### 4.3 从 RAG 后端验证完整连接

按使用说明书配置并启动 RAG 后，从其实际运行环境执行：

```bash
# Compose 部署；使用附加 Compose 文件时带上相同的 -f 参数
docker compose exec backend python -m scripts.check_runtime --live-model
```

主机部署则在 RAG 的终端、沿用其 `DATABASE_URL` 和 `DATA_DIR` 等配置执行：

```bash
uv run --no-sync python -m scripts.check_runtime --live-model
```

`embedding.ok=true`、`shape=[1,512]` 且范数接近 1，说明后端实际完成了向量调用。该探针还会检查数据库和 CLI，并真实调用生成模型的文本与图片能力；生成项失败应单独排查，不能归因于向量 API。去掉 `--live-model` 只检查配置，不验证模型编码。

修复后在页面对 failed 文档点击“重试处理”，不必重复上传。只有完整处理为 `ready` 的文档才参与检索。

## 5. 日志、停止与重启

日志位于仓库的 `data/qzhou-embedding.log`。Linux 用 `tail -n 100 -F data/qzhou-embedding.log` 跟踪；Windows 用 `Get-Content -LiteralPath 'data/qzhou-embedding.log' -Tail 100 -Wait`。在日志查看终端按 `Ctrl+C` 只结束查看。

停止前先等 RAG 的入库与问答结束，再停 RAG 后端，最后停止模型：

- 前台运行：在**运行模型的终端**按一次 `Ctrl+C`，等待进程退出。
- screen 运行：执行 `screen -r qzhou-embedding` 回到模型终端，按 `Ctrl+C` 等待退出；不再使用该 shell 时输入 `exit` 关闭会话。
- 运行 `nvidia-smi` 并重新访问 `/health`，确认本服务进程释放显存、端口关闭。存在其他 GPU 进程时，整张卡显存不一定归零。

不要使用 `pkill python` 或结束所有 Python 进程。重启时重新激活模型环境、设置密钥并运行同一启动命令；仅修改 RAG `.env` 不会更新正在运行的模型进程。更换密钥必须更新模型和 RAG 两端并分别重启。停止模型不会删除 `models/` 权重，下一次启动可复用。

## 6. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 连接失败 / 502 | 先检查模型机器的 `/health` 和日志，再检查监听端口、网关、云安全组与防火墙；从后端所在环境复验 |
| Docker 内访问失败 | 不要用容器内 `127.0.0.1` 指宿主机；核对 `host.docker.internal` 解析、Linux 映射及防火墙 |
| `/embeddings` 返回 404 | Base URL 应包含 `/v1`，不应含末尾 `/embeddings`；网关也需保留正确路径 |
| 返回 401 / 403 | 密钥不为空、没有多余 `Bearer ` 前缀且两端一致；检查网关是否保留请求头，以及两端是否重启加载新值 |
| 编码返回 Unknown embedding model | `EMBEDDING_MODEL` 应为服务公开的全名或别名；已有库更改模型标识可能触发配置档案不匹配 |
| 缺少 `2_Dense` / 维度不对 | 重新获取完整模型；不能只下载 Qwen 基础权重、跳过投影或伪造向量 |
| `LossKwargs` 等导入错误 | 核对模型自定义代码与 Transformers 版本；先复现本文独立环境，不盲目升级所有库或套用任意 vLLM 命令 |
| CUDA / BF16 不可用 | 检查 GPU、驱动、PyTorch CUDA 构建及解释器路径；CPU wheel 无法运行当前脚本 |
| 显存不足 | 释放本服务不需要的 GPU 占用、缩短输入，或换用显存更充足的机器；本脚本不提供 CPU/量化自动回退 |
| 超时 / 输入过长 | 等待模型加载，按实际延迟调整客户端超时；超出服务的 4096-token 上限时拆分输入 |
| `MODEL_OUTPUT_INVALID` | 这是生成模型的输出或引用校验问题，应查看 RAG 后端日志；不是向量密钥错误 |

本文说明部署方法与验证标准。具体环境的历史结果见 [开发与验证记录](progress.md)，不将一次部署的结果当作新机器的通过保证。
